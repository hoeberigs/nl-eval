nl-eval

A Dutch evaluation suite for language models, in three layers: native grammar, translated breadth, and applied Dutch that no existing benchmark covers. No LLM judge, so a run is deterministic and costs about a cent.

GitHub Attribution & licences

ResultsLeaderboard

Accuracy with a 95% Wilson interval, against the chance baseline for the layers included in that run. Control runs are listed and labelled rather than hidden: a leaderboard that omits its own baselines is asking to be taken on trust.

CompositionThe three layers

The layers are scored separately and never blended into one number. A single headline mixing native grammar with translated knowledge cannot be read as either, and the chance baseline differs by layer.

LayerSourceItemsLicence
L1 · grammar BLiMP-NL — native Dutch minimal pairs, 22 phenomena, human acceptability ratings —CC-BY-4.0
L2 · breadth Global-MMLU (nl) — translated knowledge and reasoning —Apache-2.0
L3 · applied Hand-written: de/het, tussen-n, diminutives, word order, idioms, false friends, u/je register, notation, civics, BE/NL —MIT

L1 and L2 are fetched at run time and never redistributed: they download on first use into a local cache, so their licences stay with their publishers. --suite core needs no network.

Prior artDutch is not an unserved language

This is not the first Dutch benchmark and does not replace one. Anyone evaluating a model on Dutch should start with EuroEval (formerly ScandEval), the maintained Dutch leaderboard covering sentiment, NER, linguistic acceptability and reading comprehension, with confidence intervals and a runnable library. DUMB covers Dutch NLU for encoders, and the Open Dutch LLM Leaderboard preceded EuroEval.

Three narrow things those leave open, which is what this suite is for: most Dutch leaderboard tasks are machine-translated, so provenance is labelled here and layers are never blended; orthography, register and notation are untested anywhere I could find, which is what L3 covers; and BLiMP-NL's human acceptability ratings are underused, which is the next thing worth building.

Treat this as a supplement to EuroEval, not a replacement.

Why not translationTranslating an English benchmark is the weaker move

It is already done. Global-MMLU ships Dutch under Apache-2.0. Re-translating MMLU duplicates free work.

Translated items largely measure translated English. The questions keep their source-language shape and culture-bound knowledge does not survive the trip, so a model can score well on translated Dutch while handling actual Dutch badly.

The hardest Dutch has no English source. There is no English sentence that becomes “welk lidwoord hoort bij beleid”. Article assignment, the tussen-n, and the u/je register cannot be produced by translating anything, which is why L3 is written by hand.

IntegrityThe controls

Two baselines ship with the suite and cost nothing to run. If always-a ever scores meaningfully above chance, the answer key has drifted onto one letter and the suite is measuring letter preference rather than Dutch. --validate checks this automatically, including for the externally-sourced layers.

$ nl-eval --provider echo       # answers nothing at all
accuracy 0.000   chance 0.339   189/189 replies unparseable

$ nl-eval --provider always-a   # always answers "A"
accuracy 0.354   chance 0.339   lift +0.016

$ nl-eval --suite all --provider always-a
n 928   accuracy 0.371   chance 0.387   lift -0.016
  L1 blimp    440   0.500   (exactly 2-choice chance)
  L2 mmlu_nl  299   0.191   (key leans away from A)
  L3 core     189   0.354

Across all three layers a fixed-letter guesser scores slightly below chance.

Running itFree and paid paths

pip install -e .

nl-eval --validate                                  # no network, no spend
nl-eval --provider ollama --model qwen2.5:7b --suite all   # free, local
nl-eval --provider openai --model gpt-5-mini --suite all --max-spend 0.50

--max-spend is a euro ceiling checked before the first API call. The run refuses to start if the estimate exceeds it and says what to cut. The price table deliberately over-estimates.

ScoringMinimal pairs are scored by likelihood

BLiMP-NL is designed to be scored by comparing the log-likelihood a model assigns to the grammatical and the ungrammatical sentence, not by asking it to pick one. A forced choice can be right for the wrong reason, and it measures instruction-following as much as grammar. Chat APIs will not return the likelihood of text they did not generate, so this needs local weights.

What that is worth, on one model and the same 440 items:

Scoring methodAccuracyNote
Log-probability87.3%95% CI 83.8–90.1%
Forced choice0.0%440/440 replies unparseable

Identical model, identical items. GroNLP/gpt2-small-dutch knows Dutch grammar perfectly well; it cannot follow a multiple-choice instruction, because it is a base model. Scored by forced choice it looks like it knows nothing, which would have been a completely false reading.

ContaminationThese items are public

A model trained after publication may have seen them, and a contaminated model scores high without knowing any Dutch. Every benchmark has this problem; most do not say so. This one publishes a canary GUID that exists nowhere else — if a model reproduces it, it trained on this repository and its score is void.

The layers carry different risk and should not be read as if they shared one. BLiMP-NL and Global-MMLU predate most training cutoffs and are very likely in large corpora already; the hand-written layer was published here first. The honest fix is a held-out split that is never published, and this suite now has one.

Run a model on the published items and on items it cannot have seen, then compare. The gap is always read against the noise floor for the smaller split, so a few points of difference is reported as noise rather than as an accusation.

$ nl-eval --contamination-check results/m.json results/m-held.json
public 0.97   held-out 0.55   gap 0.42   noise floor 0.08
CONTAMINATION LIKELY: the model scores far better on published items

Moving an item out of a repository does not un-publish it. Git keeps history, so anything ever committed is compromised for this purpose permanently. The held-out directory is gitignored from the outset and the status command refuses to call a set clean if git is tracking it or ever did: held-out items must be written privately, not moved there.

The repository publishes a commitment manifest — ids and salted answer hashes only. It proves the set existed at this date without revealing a single question or answer, and the salt stays with the private items so the hashes cannot be brute-forced.

StatisticsCan one model actually beat another

Most leaderboards print two accuracies and order the rows, which invites the reader to treat a two-point gap as real. On a suite this size it usually is not. --compare settles two runs with McNemar on the discordant items plus a paired bootstrap for the size of the difference.

$ nl-eval --compare results/a.json results/b.json
accuracy  0.730 vs 0.746      difference -0.016
95% CI    [-0.106, +0.074]    p 0.820
verdict   not distinguishable on this suite

Every run also reports the smallest gap the suite could reliably detect, so a reader can see when it is simply too small to settle a question:

Human alignmentDoes it find the same things hard that people do

Accuracy says how often a model was right. It cannot say whether a model failing at 85% fails where Dutch speakers hesitate, or on violations every native speaker catches instantly.

BLiMP-NL makes that answerable: nine of the ten hand-written sentences per paradigm carry 7-point acceptability ratings from at least 30 native speakers. Correlating the human difficulty of each paradigm against the model's accuracy on it gives a human-alignment score, and it works on ordinary forced-choice answers with no log-probabilities needed. Positive means the model finds the same violations easy that people do; near zero means it is often right for different reasons.

The ratings are not bundled and never downloaded automatically. They sit in the Radboud repository under CC BY-SA 4.0, which is share-alike and stricter than the CC-BY on the sentence pairs, and the portal asks for an account.

LimitsWhat this does not measure

BLiMP-NL is scored as a forced choice here, not by comparing the log-probability of each sentence as the corpus intends. A forced choice can be right for the wrong reason.

Human alignment is paradigm-level, not item-level. It correlates per-paradigm accuracy against per-paradigm human deltas, which is what forced-choice answers support. Item-level correlation would need per-sentence log-probabilities.

Multiple choice is recognition, not production. A model can pick pannenkoek from two options and still misspell it when writing freely.

L3 is written by one author and has not been reviewed by a second native speaker. A native review is advisable before publishing L3 results. L2 inherits Global-MMLU's translation quality, including its errors.
